0.14.x → 0.15.x
===============

No structural change: no field was renamed, moved, added or removed, and every 0.14 workspace
keeps its layout. What changed is that a set of constraints the model always intended is now
declared on the fields themselves — which makes them visible in the JSON Schema exported from
:class:`~flync.model.flync_model.FLYNCModel`, and makes a few previously-tolerated values fail
validation.

Breaking — YAML schema
----------------------

Empty identifiers and references are rejected
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Required identifier and reference strings now declare ``min_length=1``. An empty value was
previously accepted and only surfaced further along as a confusing reference error (an empty
``pdu_ref`` reported as ``unknown PDU ''``), or silently produced an unnamed object.

Affected are the required ``name``, ``id``, ``label``, ``group``, ``service``, ``profile_id``,
``ecu_name``, ``controller_name``, ``interface_name``, ``bus_name`` and ``*_ref``
(``pdu_ref``, ``bus_ref``, ``socket_ref``, ``frame_ref``) fields across every domain.

.. code-block:: yaml

   # no longer valid
   - name: ""
     pdu_ref: ""

Optional fields are unaffected: leaving one out, or setting it to ``null`` where the model
allows that, behaves exactly as before.

Negative values are rejected on quantities that cannot be negative
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``ge=0`` was added to:

* MACsec MKA timers — ``hello_time``, ``bounded_hello_time``, ``life_time``,
  ``sak_retire_time`` (matching ``sak_rekey_time``, which already declared it),
* PTP time-receiver timeouts — ``sync_timeout``, ``sync_followup_timeout``,
* HTB shaping — ``classid``, ``rate``, ``ceil``, ``priority``, and ``HTBFilter.filter_priority``,

Container PDU header field widths are capped at 32 bits
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``ContainerPDUHeader.id_length_bits`` and ``ContainerPDUHeader.length_field_bits`` now
declare ``le=32`` in addition to the existing ``multiple_of=8``. Widths above 32 bits were
previously accepted although no supported container format uses one.

.. code-block:: yaml

   header:
     id_length_bits: 40     # no longer valid, must be 0, 8, 16, 24 or 32
     length_field_bits: 64  # no longer valid, must be 0, 8, 16, 24 or 32

Additive — YAML schema
----------------------

``J1939Frame.length`` widened to support Transport Protocol payloads
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``J1939Frame.length`` was previously a literal fixed at ``8`` bytes (a single-frame J1939
parameter group). It is now an ``int`` in ``1..1785`` with a default of ``8``, so a Transport
Protocol message whose payload is shipped over multiple physical J1939 frames can be modelled as a
single PDU. Existing ``8``-byte frames load unchanged.

New optional instrumentation overlay
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The optional ``instrumentation/`` folder (:ref:`flync_4_instrumentation <instrumentation>`) wraps the
measurement points under an ``Instrumentation`` container on the root model:
``flync_model.instrumentation`` is ``None`` without the folder, otherwise an
``Instrumentation`` whose ``measurement_points`` load from
``instrumentation/measurement_points.flync.yaml``. Each measurement point is identified by
its ASAM CMP / TECMP interface ids and taps exactly one medium:

* ``type: ethernet_ports`` — one or two ECU ports of a point-to-point Ethernet link, one
  ``interface_id`` per port (two ports must be the two ends of the same connection),
* ``type: ethernet_bus`` — one interface id for an ``ethernet_multidrop`` segment, by connection id,
* ``type: can_bus`` — one interface id plus the ``payload_types`` captured on the bus
  (``can_fd`` is required exactly on ``fd_enabled`` buses),
* ``type: lin_bus`` — one interface id for a LIN bus.

``name`` and every interface id are unique across the overlay, and ``flync_model.instrumentation``
is an ``Instrumentation`` instance carrying ``.measurement_points``. No 0.14 workspace has the
folder, so workspaces keep their layout; adding the overlay is purely optional.

Breaking — Python API
---------------------

List fields that were never ``None`` after validation are typed as plain lists
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

These fields are typed ``list[...]`` instead of ``Optional[list[...]]``. This removes ``null`` from the
exported JSON Schema. A type checker (mypy, pyright) now rejects ``None`` passed to the constructor or
assigned to the field; at runtime ``None`` is still accepted and becomes ``[]``.

* ``TrafficClass.frame_priority_values``, ``TrafficClass.internal_priority_values``
* ``PTPTimeTransmitterConfig.tlv``
* ``VirtualControllerInterface.multicast``, ``VLANEntry.multicast``
* ``PortScopedAction.ports``, ``TCAMRule.match_ports``, ``TCAMRule.action``

The following fields additionally change loading behavior: a ``null`` used to be stored as ``None`` and now
loads as ``[]``:

* ``Socket.multicast_tx``, ``AVTPMulticastEndpoint.multicast_tx``
* the runtime-only ``ECU.multicast_groups`` and ``IPv4AddressEndpoint.sockets`` /
  ``IPv6AddressEndpoint.sockets``

Value encoding bounds are always integers
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``TextEntry.from_value`` / ``to_value`` and ``BitfieldState.from_value`` / ``to_value`` are typed
``int`` instead of ``Optional[int]``; they were always filled from ``value`` or given explicitly, and
``None`` was never a valid bound. An explicit ``value: null`` without ``from_value``/``to_value`` is now
reported as a type error instead of an internal assertion error.

``EthernetInterfaceConfig.name`` may be ``None`` (typing only)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The property was previously untyped and is now annotated ``str | None``: the name is propagated from the
owning :class:`~flync.model.flync_4_ecu.controller.EthernetInterface` and is ``None`` before that happens.
Runtime behavior is unchanged; type checkers now require a ``None`` check before using the name as ``str``.

``FLYNCWorkspace.get_semantic_object_from_model()`` removed
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The deprecated single-result lookup is gone. Use ``get_semantic_objects_from_model()``, which returns every
semantic object registered for the model; ``objects[0] if objects else None`` gives the former result.

Deprecated — Python API
-----------------------

``ECUPort.get_internal_connected_component()`` ignores its ``ecus`` argument
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The ``ecus`` parameter was never used. It is still accepted for backwards compatibility but passing a
value (other than ``None``) emits a ``DeprecationWarning``. Call ``port.get_internal_connected_component()``.

Additive — Python API
---------------------

* ``ECUPort.qualified_name`` — ``"<ecu>:<port>"`` once the port is bound to its ECU, else the port name.
* ``SOMEIPMethod.has_response`` — ``True`` for request/response methods, ``False`` for
  fire-and-forget ones. It replaces the empty ``__init__`` overrides that kept ``SOMEIPMethod``
  abstract, so constructing the concrete method classes is now type-checked by mypy.
* ``InternalConnection.ecu`` now returns the owning ECU; it was always ``None`` before, so code that checks
  ``connection.ecu is None`` now takes the other branch.
